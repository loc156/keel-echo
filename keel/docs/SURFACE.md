# Keel 表面语法（v1）

表面语法是 `keelld` 的第二个前端：它把 `let` / `if` / `while` / `fn` 这类写法改写成
**核心 token**，然后走完全相同的装载与执行路径。

它的设计原则只有一句：**只脱糖，不加运行时语义**。

- `let` 和 `x = e` 都是 `store` —— 这门语言没有块作用域，变量就是全局的；
- `if` / `while` 直接落到核心的 `if` / `then` / `begin` / `again` / `break`；
- `fn name { ... }` 就是核心的 `"name" { ... }`，运行时定义块；
- 没有局部变量、没有闭包、没有带参函数 —— 这些是运行时改动，不是糖。

用法：装载时把 `keelld::Options::syntax` 设成 `keelld::Syntax::Surface`，其余
（`load_text` / `load_file` / `install` / `execute` / `include`）完全不变。
`Program::tokens` 里拿到的已经是核心 token，`Program::source` 还是原文。
`install` 见到 Surface 语法时会额外注册一条 `s.add`（见下）。

一个硬约束：**表面语法前端产生的诊断全是 `Sev::Error`，没有警告**。任何一条都会让
`Program::ok()` 为假，`install` 直接拒绝装载——不会出现"跑一半"的表面程序。

## 1. 词法规则

表面语法有自己的词法器（不复用核心的 `tokenize`），规则如下：

| 项目 | 规则 |
| --- | --- |
| 空白 | 空格 / 制表 / 回车跳过；**换行是语句分隔符** |
| 语句分隔 | 换行或 `;`；表达式内部遇到换行就结束该表达式 |
| 括号内换行 | `(` 深度大于 0 时换行被忽略，调用参数可以折行 |
| 注释 | `//` 到行尾；`#` 到行尾（`Options::hash_comments`，默认开；这里不要求 `#` 在 token 起点，和核心词法器不同） |
| 标识符 | 字母或 `_` 开头，可含数字；允许 `a.b` 形式（点后面必须还是标识符字符），`..` 是独立运算符 |
| 数字 | 十进制、小数点、指数（`1`、`3.5`、`1e-3`）；**不带符号**，负号是一元 `-`；`0x10` 会被切成 `0` 和 `x10` |
| 字符串 | 单引号或双引号；支持 `\n` `\t` `\r` `\\` `\"` `\'`，其它 `\x` 得到字符 `x` |
| 其它字符 | 报错 `不认识的字符: '…'`（引号里是那个字符） |
| 未闭合字符串 | 报错 `字符串没有闭合（缺右引号）` |

表面语法只把**已解转义**的字符串重新包成核心 token：内容里有双引号就用单引号包，
有单引号就用双引号包；两种都有就报错（见第 6 节）。

## 2. 脱糖总表

下表左边是表面写法，右边是它产生的核心 token。`A` / `B` 表示任意语句序列，
`e` / `c` 表示表达式。

| 表面写法 | 核心 token |
| --- | --- |
| `let count = 0` | `0 "count" store` |
| `count = count + 1` | `"count" load 1 s.add "count" store` |
| `print e` | `e 的 token... println` |
| `print(e)` | `e 的 token... println`（括号只是分组，不是指令调用） |
| `if c { A }` | `c... if A... then` |
| `if c { A } else { B }` | `c... if A... else B... then` |
| `if c { A } else if d { B } else { C }` | `c... if A... else d... if B... else C... then then` |
| `while c { A }` | `begin c... not if break then A... again` |
| `fn f { A }` | `"f" { A... }` |
| `fn f(x) { A }` | `"f" { A... }` + 一条错误诊断（形参被整段丢弃） |
| `return e` | `e 的 token... ret` |
| `return` | `ret` |
| `include "p.keel"` | `"p.keel" include` |
| `raw { ... }` | 花括号内容逐 token 原样输出（不含外层括号） |
| `f(args)`，`f` 是本文件的 `fn` | `args... "f" call` |
| `invoke(e)` | `e... call` |
| `g(args)`，`g` 不是本文件的 `fn` | `args... g` |
| `a + b` | `a... b... s.add` |
| `a .. b` | `a... b... concat` |
| `a - b`、`a * b`、`a / b`、`a % b` | 同名核心指令 |
| `a == b`、`a != b`、`a < b`、`a <= b`、`a > b`、`a >= b` | 同名核心指令 |
| `a && b`、`a and b` | `a... b... and` |
| `a || b`、`a or b` | `a... b... or` |
| `!a`、`not a` | `a... not` |
| `-a` | `a... neg` |

关于 `+` 和 `..` 的区别：`+` 脱糖成 `s.add`，**任一侧是字符串就拼接，否则数值相加**；
`..` 脱糖成 `concat`，永远先 `toString` 再拼接。`s.add` 只在 Surface 程序装载时注册，
核心程序里写 `s.add` 只会得到一个字面量。

## 3. 表达式与优先级

从低到高：

1. `or` / `||`
2. `and` / `&&`
3. `==` `!=` `<` `<=` `>` `>=`
4. `..`
5. `+` `-`
6. `*` `/` `%`
7. 一元 `-` / `!` / `not`
8. 调用 `f(...)`、括号 `( ... )`

所有二元运算符左结合。操作数只可能是：数字字面量、字符串字面量、`true` / `false` / `nil`、
变量名（编译成 `"名字" load`）、函数/指令调用、括号表达式。

`and` / `or` **不是短路的**：两侧都会求值，然后由核心的 `and` / `or` 用真值规则合并。
所以不要依赖 `x != 0 and 1 / x > 2` 这种写法避免除零。

## 4. 调用规则

- 名字后面跟 `(` 才算调用；调用参数按书写顺序先求值（留在栈上），再决定怎么调。
- **本文件的 `fn`**：编译成 `"名字" call`。`fn` 名字在**整份文件**里预扫描过，所以
  编译器认识"这是块不是指令"，调用写在定义前面也能生成 `call`。但块本身仍然是
  **运行时**定义的：在执行到那一行 `fn` 之前调用，运行时会报 `call: unknown block`。
  前向引用只保证编译形状正确，不保证运行时已经存在。
- **其它名字**（`println`、`ui.button`、`str`、`s.add`……）：不加 `call`，直接当指令用。
  也就是说"调用"外部块时你写的是名字，实际执行的是同名的**指令**；名字不存在时它会被
  当字面量压栈（见第 6 节第 18 条）。
- **外部块**（别的文件、或运行时算出来的名字）：只能 `invoke(...)`，它会脱糖成 `call`。
  `invoke` 只接受一个参数。
- 不在调用位置的裸词是**变量读取**：`print x` 里的 `x` 编译成 `"x" load`。

## 5. 语句形式

- `let 名字 = 表达式`、`名字 = 表达式`：都脱糖成 `... "名字" store`。赋值目标只能是不带
  点的词。
- `print 表达式`：**固定脱糖成 `println`**，也就是一定换行。
- `if ... { } [else ...]`：`else` 必须紧跟在 `if` 的块后面；`else if` 支持。
- `while ... { }`：先判后做，条件每轮重新求值。
- `fn 名字 { }`：定义块；不支持形参。
- `return [表达式]`：脱糖成 `... ret`；带值时值是留在栈上的，没有"返回值语法"。
- `include "路径"`：路径必须是字符串字面量。
- `raw { ... }`：核心 token 逃生仓，里面的东西逐 token 原样输出，不解释 `let` / `fn`。
- 单独一个词（`break`、`drop`、`dup`、`halt` 之类）：当指令语句输出，**不是变量读取**。
- 其它情况按表达式语句处理：求出值留在栈上，**不会自动 `drop`**。

## 6. v1 限制（逐条）

### 函数与名字

1. **`fn` 不支持形参。** 写 `fn add(a, b) { ... }` 会得到诊断
   `fn 暂不支持参数；调用方按栈约定传值（v1 限制）`，括号里的内容被整段跳过。
   调用方按栈约定传值：先压参数，再 `add()`。
2. **形参不会变成局部变量。** 因为括号被丢弃，`fn f(a) { a + 1 }` 的块体编译成
   `"f" { "a" load 1 s.add }`：`a` 是一次**全局变量读取**。所以就算绕开那条诊断，
   `f(3)` 也不会把 3 绑定到 `a` —— 块体只会去读全局变量 `a`（没存过就报"未定义变量"）。
3. `fn` 的块名不能带 `.`。`fn a.b { ... }` 报 `fn 的块名不能带 '.'`。
4. `let` 的变量名不能带 `.`。`let a.b = 1` 报 `let 的变量名不能带 '.'`。
5. 赋值语句只识别"**不带点的词** + `=`"这种形状。`m.x = 2` 不构成赋值：`m.x` 被当成
   变量读取，随后 `=` 处报 `这里需要表达式`。
6. 没有复合赋值（`+=`、`-=` 等不存在）。
7. `fn` 的可见性只限**本文件**：调用判断依赖对整份文件 token 的预扫描，被 `include`
   进来的 `fn` 不在这个集合里。跨文件调用一律用 `invoke("名字")`。
8. 名字可见不等于块已存在：`f()` 写在 `fn f { ... }` 之前时，编译出的是 `"f" call`，
   运行到那一行会报 `call: unknown block 'f'`（不中断执行，但结果是错的）。要调用就先
   定义。

### 语句与块

9. `if` / `while` / `fn` 的块必须是 `{ ... }`。`if 1 print 2` 报 `这里需要 '{'`，
   而且仍然会生成半截 token（`1 if then 2 println`）——靠诊断拦住，不要靠它跑。
10. `else` 必须属于某个 `if`；单独写 `else` 报 `else 没有匹配的 if`。
11. `let` 后面必须是 `= 表达式`。`let x` 报 `let 需要 '= 表达式'`。
12. `include` 后面必须是**字符串字面量**。`include foo` 报 `include 后面需要字符串路径`；
    路径不能由表达式算出来（`invoke` 那种写法这里不适用）。
13. `raw` 后面必须是 `{ ... }`；不闭合报 `raw 的 '{' 没有闭合`。
14. 表达式缺操作数时报 `这里需要表达式`。典型触发：`print` 后面没有表达式、`1 +` 结尾、
    表达式位置出现 `=` 或 `{`。

### 字符串与 token

15. **一个字符串不能同时含单引号和双引号。** 报
    `字符串同时含单双引号，核心 token 无法表示（v1 限制）`；此时那个字符串 token 会被
    丢掉（表达式因此缺操作数），但装载已经被诊断拦住了。
16. 转义只认 `\n` `\t` `\r` `\\` `\"` `\'`；其它 `\x` 得到字符 `x`，不做报错。
17. 表面语法的字符串里不能靠 `//` 或 `#` 当普通文本——注释在词法阶段就被切掉了
    （字符串内部除外）。

### 表达式与语句

18. **未定义的词不会报错，只会变成字面量。** 例如在 `while` 里写 `continue`：没有
    `continue` 指令，它会被当成指令语句输出，运行时成为一个字符串压在栈上，每轮一个，
    而且 `ok` 依然为真。没有 `for`、没有 `switch`、也没有 `continue`。
19. 表达式语句不自动 `drop`：`1 + 2` 单独一行会把 3 留在栈上。
20. 单独一个变量名成不了语句：`x` 单独一行会输出**指令词** `x`（运行时是字面量 `"x"`），
    不是读取变量。要读变量就让它参与表达式，或者写 `print x`。
21. 没有局部变量、闭包、数组字面量、结构体/对象字面量；容器只能用核心的
    `list` / `map` 构造（`let xs = list` 这种写法是把指令 `list` 当变量读，**不是**构造
    空列表——要写 `let xs = 0` 之后 `xs = list` 也不行，因为 `list` 在表达式位置同样是
    变量读取。容器只能在 `raw { ... }` 里构造，或者由宿主/C++ 指令预置）。
22. 所有诊断都是 `Sev::Error`（没有警告），一条就让 `Program::ok()` 为假。

### 装载

23. 表面前端**不检查** `Options::max_tokens`（核心词法器会检查）；`max_bytes` 仍由
    `load_text` / `load_file` 统一检查。

## 7. 一个完整的对照示例

表面源码：

```keel-surface
let n = 0
fn bump { n = n + 1 }
while n < 3 { bump() }
print n
if n == 3 { print "three" } else { print "other" }
```

它编译出来的核心 token 序列（也就是 `Program::tokens` 里的内容，顺序完全一致）：

```text
0 "n" store
"bump" { "n" load 1 s.add "n" store }
begin "n" load 3 < not if break then "bump" call again
"n" load println
"n" load 3 == if "three" println else "other" println then
```

这段脚本运行后依次打印 `3`、`three`。注意三点：`fn` 只留下 `"bump" { ... }`（块在
执行到那一行时定义）；`while` 的条件被反转成 `not if break then` 放在循环体前面；
`print n` 是 `"n" load println`。

## 8. 常见坑

- **`print` 一定是 `println`。** 想要不换行只有 `raw { ... print }`（`print` 关键字在
  语句开头就被消费了，`print(x)` 也只是 `x println`，到不了核心的 `print` 指令）。
- **语句开头的指令名会被当成变量读取。** `ui.text "hi"` 会编译成 `"ui.text" load "hi"`，
  运行时报 `undefined variable 'ui.text'`（写 `ui.*` 时最容易撞上）。两种能跑的写法：
  调用形式 `ui.text("hi")`，或把操作数写在前面 `"hi" ui.text`。
  混用时要留意：`str(n) concat ui.text` 里，`str(n)` 已经把语句结束掉，后面的 `concat`
  又处在语句开头，同样会变成变量读取。写成嵌套调用 `ui.text(concat("n = ", str(n)))`
  就不会有这个问题。
- **`fn` 的参数是幻觉。** 参数列表被丢弃、括号里的名字在块体里是全局变量读取。
  正确写法是：块体只从栈上取操作数，调用方先压值再 `f()`。
- **裸变量不成句。** `x` 单独一行是指令词，不会读取变量。
- **表达式语句会留垃圾。** 栈上残留值会影响后面的 `depth`、`get`、`store` 等操作数顺序。
- **跨文件调不到 `fn`。** 用 `invoke("名字")`。
- **拼错的词不会报错。** 它会变成字面量（第 6 节第 18 条），错误往往延迟到后面才炸。
- **`s.add` 只有 Surface 程序才有。** 在 `raw { ... }` 或核心程序里写 `+` 不会走 `s.add`。
- **别拿表面语法当核心语法的超集。** `raw { ... }` 之外没有"原样透传"的通道；
  两种语法各自有一份词法，`#` 注释的边界、字符串转义都不同。

核心语言本身（token、块、变量、循环、错误与限额）见 [LANGUAGE.md](LANGUAGE.md)；
装载器契约见 [LOADER.md](LOADER.md)；指令清单见 [REFERENCE.md](REFERENCE.md)。
